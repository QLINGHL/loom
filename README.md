# Loom — AI 原生操作系统（架构原型实现）

> 把大模型当作外设，而不是内核的操作系统。
> 确定性内核持有全部执行权，模型只负责理解与提议，两者之间隔着一条可审计的窄腰。

本仓库是 Loom 架构设计的可运行原型实现（P0 阶段：用户态运行时，不碰真内核），
按设计文档 v2 落地核心机制，并用文档第 23 章的 MVP 垂直切片
（出差行程：邮件 + 日历 + 本地文件）做端到端验证。

## 核心命题（v2）

1. **AI 提议，内核执行** — 模型永不进入可信计算基；一切副作用必须经内核能力校验后代为执行。
2. **信任是数据的属性** — 上下文带信任标签（user / verified / untrusted），污点随数据流动传播。
3. **一切副作用必须可补偿** — 事务 + 幂等键 + 补偿动作；不可补偿的动作走最严确认路径 + 冷静期。
4. **确定化（北极星）** — 重复的意图逐步编译成确定性宏：同一个意图每重复一次，就更便宜、更快、更安全，直到完全不需要模型。

## 实现语言：Rust

按设计文档第 20 章的既定路线，用户态组件用 **Rust** 实现：内存安全对长期运行、
处理不可信输入的服务是刚需；且 Rust 的所有权 / 仿射类型与第 7 章的线性效果
类型（⊸ 消费一次）天然对位——能力令牌与线性效果可以直接建模为按值消费的
类型，而不是运行时模拟。

## 实现说明（完整 vs 简化，如实标注）

**完整实现**（有真实逻辑与专门测试，非桩）：

- 密码学：SHA-256 / HMAC-SHA256 手写实现，RFC 4231 与 FIPS 已知答案向量验证；零外部依赖，离线可构建。
- 能力系统：HMAC 签名令牌、衰减单调收窄、短租约、撤销、按次消费、负能力沿委托链传播；线性能力按值 move 消费，二次消费在编译期不可能。
- 效果类型检查：线性效果（send/transfer/delete）重复消费在执行前被拒；能力可达性静态检查；风险由效果集合推导。
- 污点追踪：标签格 join 传播；摘要继承最高污点；执行器对 untrusted 污点 + 中/高风险计划强制 yield。
- 双模型分离：`Planner` 类型上只有模型、没有任何工具/内核句柄；`Executor` 只消费 Plan IR。注入场景有端到端测试（被拦于类型检查 / yield 两道关，银行工具零调用）。
- 记忆：无出处拒绝落库；L1→L2 晋升门（可信源 + 衰减置信度 ≥ 0.7 + 高风险类目双源）；半衰期衰减；recall 低置信给出 needs_yield。
- 事务：幂等键回放、补偿栈逆序回滚、三档可补偿性、不可逆动作冷静期暂存-提交时分发、undo 一等公民且报告如实区分「已补偿/不可补偿」。
- 确定化：结构指纹 L1 缓存；≥5 次成功 + 用户确认编译 L2 宏（变化叶子自动发现为槽位）；前置条件逐次校验、连续 3 次失败降级进重编译队列；工具 schema 版本漂移立即失效；L3 触发器需稳定 ≥20 次 + 显式授权 + 预算上限。
- 内核与账本：十个原语面；每次 act 落哈希链账本（谁/何时/为何/哪张能力），可回放、可验链篡改。
- 注意力调度：AIMD + 慢启动、max-min 公平、中断定价、P0–P3 分级、同意图合并、拒绝后静默期；推理调度：驻留 ≤2 + LRU、驻留感知路由、字节与前缀命中记账、准入排队/降级；五类 Agent 配额在内核入口强制。
- 投机执行：四验证谓词合取、预算门槛（电量/耗时占比/后台）、不可投机屏障在 act 入口串行化。
- 现实缓存：MESI 四状态与冲突升级；工具注册表：描述哈希钉住、Rug Pull 自动失效、代调用强制显式令牌。
- 黑板：只追加事实库，条目永不原地修改；取代只能追加新条目并标注取代对象，存活状态由扫描派生（取代时不改旧条目）；取代仅限同 key 的存活条目，拒绝未知/已取代/跨 key 取代以防历史分叉；每条事实强制出处、无出处拒写，信任标签由出处在发帖时派生并固化；读者可按信任等级过滤当前事实，过滤只隐藏不删除。
- 看门狗：状态指纹无进展判定；意图版本化 diff（保留仍有效的已完成步骤）。

**简化模型**（语义成立，但不是生产形态）：

- 这是**用户态原型**，不是真微内核：没有进程隔离、没有 IPC、没有硬件驱动；「内核」是同进程内的可信对象，靠 Rust 类型与 API 形状维持边界。
- 推理调度是**记账级模拟**：驻留/搬运/前缀命中按声明的权重大小与带宽参数计算，不接真实 NPU/GPU，不加载真实模型。
- 模型是确定性脚本 `FakeModel`，不接真 LLM；计划器的「理解」由脚本模式模拟（包括被注入说服的模式）。
- 工具是进程内 Rust 对象（demo 里是带共享状态的假工具），不是沙箱化插件；工具的「世界」是内存状态。
- 冷静期采用「暂存—提交时分发」模型：不可逆动作在 commit（且冷静期满或用户确认）时才真正调用工具；真实系统里部分动作（如已发出的网络请求）无法这样暂存，需要对端配合。
- 时间是可注入时钟（`Clock` trait），测试与演示用手动时钟推进；没有真实定时器/后台线程，看门狗与投机都是被动调用式评估。
- 注意力调度的「用户」由回调（decider）扮演；max-min 分配是单轮静态计算，不含真实 UI 呈现与抢占。
- L0 即时编译只保留草稿集语义（宏晋升路径 L1→L2→L3 完整），未做表达式级 DSL；宏槽位仅支持参数叶子替换，不含控制流泛化。
- 记忆的「语义相关性」是词元重叠打分，不是向量检索；晋升的双源 corroboration 按「同 key+fact 不同来源」计数。
