# Loom — AI 原生操作系统（架构原型实现）

> 把大模型当作外设，而不是内核的操作系统。
> 确定性内核持有全部执行权，模型只负责理解与提议，两者之间隔着一条可审计的窄腰。

本仓库是 Loom 架构设计的可运行原型实现（P0 阶段：用户态运行时，不碰真内核），
按设计文档 v2 落地核心机制，并用文档第 23 章的 MVP 垂直切片
（出差行程：邮件 + 日历 + 本地文件）做端到端验证。

## 核心命题（v2）

1. **AI 提议，内核执行** — 模型永不进入可信计算基；一切副作用必须经内核能力校验后代为执行。
2. **信任是数据的属性** — 上下文带信任标签（user / verified / untrusted），污点随数据流动传播。
3. **一切副作用必须可补偿** — 事务 + 幂等键 + 补偿动作；不可补偿的动作走最严确认路径 + 冷静期。
4. **确定化（北极星）** — 重复的意图逐步编译成确定性宏：同一个意图每重复一次，就更便宜、更快、更安全，直到完全不需要模型。

## 实现结构

| 模块 | 对应设计 | 内容 |
|---|---|---|
| `loom/kernel.py` | 第 8 章 | 微内核：十大原语、能力校验、行动账本（只追加） |
| `loom/capabilities.py` | 第 8/13 章 | 能力令牌：签名、衰减、短租约、撤销、负能力单调传播 |
| `loom/typesys.py` | 第 7 章 | 意图编译器 + 效果类型系统：线性副作用、能力可达性、风险分级 |
| `loom/taint.py` | 第 13 章 | 上下文污点追踪与传播规则 |
| `loom/memory.py` | 第 10 章 | L0–L3 记忆：出处强制、置信度半衰期、L1→L2 晋升门槛、投毒防御 |
| `loom/transactions.py` | 第 15 章 | 效果事务：幂等、Saga 补偿、三档可补偿性、冷静期、undo |
| `loom/determinization.py` | 第 4 章 | 确定化引擎：计划缓存 → 意图宏 → 触发器，前置条件与失效降级 |
| `loom/worldcache.py` | 第 11 章 | 现实缓存：E/M/S/I 状态、工具声明的一致性等级、冲突升级 yield |
| `loom/attention.py` | 第 14 章 | 注意力拥塞控制：AIMD、慢启动、max-min 公平、中断定价、P0–P3 分级 |
| `loom/schedulers.py` | 第 9 章 | 推理调度（驻留感知、带宽记账、准入控制）+ 信任调度 + Agent 五类配额 |
| `loom/speculation.py` | 第 12 章 | 投机执行：四验证谓词、投机预算、不可投机屏障 |
| `loom/watchdog.py` | 第 16 章 | 失败分类学：无进展指纹看门狗、意图版本化与漂移 diff |
| `loom/tools.py` | 第 13 章 | 工具注册表：声明式清单、描述哈希钉住（防 Rug Pull）、能力显式传递 |
| `loom/runtime.py` | 第 6 章 | AI 运行时：计划器/验证器双模型分离、结构化 IR 气闸 |
| `loom/demo.py` | 第 23 章 | MVP 垂直切片：出差行程端到端演示（含宏编译全过程） |

## 运行

```bash
python -m loom.demo        # 跑 MVP 垂直切片演示
python -m pytest tests/    # 全部测试
```

纯 Python 标准库实现（测试用 pytest），无第三方运行时依赖、无网络调用，时钟可注入以便确定性测试。
